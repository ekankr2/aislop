# AI 슬롭 (AI slop)

AI로 만든 것을 모아 놓고, 그게 슬롭인지 쓸모 있는 것인지 유저가 판단하는 커뮤니티.

경쟁 상대는 AI 탐지기다. 탐지기는 확률만 뱉고 근거를 못 주며, 모델이 좋아질수록 진다.
"AI냐"에서 멈춰서 정작 알고 싶은 "그래서 이거 괜찮냐"에 답하지 못하고, 매번 0에서 시작한다.
사람이 근거를 들고 와서 같이 판단하고 그 전적이 쌓이는 쪽이 오래 간다.

- 프로덕션: https://aislop.kr
- 스택: Bun · SvelteKit 5 · Cloudflare Workers · D1 · drizzle · Tailwind 4 · 이메일 OTP(직접 구현, 의존성 없음)

## 원칙

[사이트에 공개한 것](https://aislop.kr/about)과 같다. 요약하면:

- **축은 둘이다.** AI를 썼는지(`aiStatus`)와 그게 문제인지는 다른 문제다.
- **축 1은 증거로, 축 2는 표로 정한다.** AI 생성 여부는 사실이라 투표 대상이 아니다.
  슬롭인지 아닌지는 유저가 투표하고, 그 여론을 그대로 보여준다.
- **운영자는 슬롭인지 아닌지를 정하지 않는다.** 운영자가 하는 일은 사실 확인이다 —
  AI 여부와 근거, 분류, 원문 사본, 신고 처리.
- **AI라는 이유만으로 슬롭이 아니다.** 잘 쓴 사례도 받는다 — 전부 유죄인 기관은 아무도 안 믿는다.
- 근거 없는 AI 확인은 저장되지 않는다.
- 글은 바로 게시된다. 잘못된 글은 사후에 신고·정정·당사자 답변으로 받는다.
- 당사자 답변과 정정 요청은 비로그인으로 받고, 처리 결과는 수용·반려 모두 공개한다.
- 돈을 받고 글을 지우는 기능은 만들지 않는다.
- 데모·가짜 데이터를 쓰지 않는다. 사이트에 있는 사례는 전부 실제 사례다.

## 기여

가장 쓸모 있는 기여는 코드가 아니라 **사례**다. [aislop.kr](https://aislop.kr)에서 받는다.
반론과 정정 요청은 로그인 없이도 낼 수 있다.

코드는 이슈나 PR로. 이 저장소는 수익 사업을 하지 않는다 —
후원이 생기면 서버비와 운영에만 쓴다.

## 라이선스

[AGPL-3.0](LICENSE). 고쳐서 서비스로 돌리면 그 소스도 공개해야 한다.
남을 다루는 사이트라 규칙이 읽히지 않는 파생물이 생기면 안 된다.

저장소에 있는 건 코드뿐이다. 사례 데이터·근거 이미지·회원 정보는 여기 없다.

## 개발

```sh
bun install
bun run db:migrate:local     # 로컬 D1에 마이그레이션 적용
bun run db:migrate           # 원격 D1. ⚠️ 스키마를 바꿨으면 배포 전에 이걸 돌려라
bun run dev                  # http://localhost:3300

bun run check                # typecheck + lint + test
bun run deploy               # vite build + wrangler deploy
```

스키마 정본은 `src/lib/core/db/schema.ts`다. SQL은 손으로 쓰지 않는다 —
`bun run db:generate`가 `drizzle/`에 마이그레이션을 만든다.

의존성을 바꾸면 락파일 **둘 다** 갱신한다 — `bun install && npm install --package-lock-only`.
로컬은 bun, CI는 npm을 쓴다.

로컬에는 메일 바인딩이 없어서 로그인 코드가 메일 대신 콘솔에 찍힌다.
